# Markdown 复制与粘贴：块适配及边界设计

状态：设计、实施、解析及应用交互验收完成，正式安装并后台启动成功。日期：2026-11-06。

## 目标与复现基线

把一篇笔记「复制 Markdown」后粘贴到新笔记，恢复可编辑块、行内格式与表格结构；再次保存、打开、复制后语义保持一致。外部 Markdown 文本遵守相同规则。

本地复现文件为用户指定的《潮汕之旅.md》，只读使用，不提交私人全文或将其写入永久测试：14,848 字节、142 行、13 个 ATX 标题、3 张 HTML 表格（共 21 行）和 1 张管道表（6 行），共 4 表 27 行、8 个待办、33 个普通列表项、39 对 strong 标签、137 处数字实体。初次正则扫描只统计了 HTML 表；后续实际解析确认总数为 4 表，并通过三轮语义往返。

已确认源码原因：

- `format_cmds.rs::copy_markdown` 写入序列化文本，未提供跨编辑器的结构信息。
- `block_shortcuts.rs::paste_blocks` 仅接受当前 Editor 的 `block_clip` 精确匹配；新笔记与外部 Markdown 通常走文本替换，绕过块解析。
- `input.rs::paste_clipboard_item` 的文本路径仅尝试 URL、内部块缓存、TSV，缺少通用 Markdown 分派。
- `paste_blocks` 在验证目标是否允许插入前删除选区，且删除和插入各记历史，存在回退后结果不完整、撤销需要两次的风险。
- 文件本身包含实体编码的星号，例如 `&#42;&#42;`；它表达字面星号，不能先全局解码、再把它误认成加粗。

## 方案决策

复用 `markdown::parse / serialize` 与现有 Block、Table、Span，不为粘贴另写一套 Markdown 解析器，不新增依赖或重做视觉组件。

「复制 Markdown」通过 GPUI 剪贴板 metadata 写入版本标识 `com.block.editor.markdown.v1`，正文保持标准 Markdown；新笔记可据此明确按文档导入。代码、源码与纯文本粘贴仍优先遵守目标上下文。外部剪贴板没有该标识时按解析结果识别格式。

采用“识别内容 → 按上下文制定替换方案 → 校验 → 单次事务”的结构。解析出块不等于任何位置都能插入块，拒绝时保持正文、选区、撤销栈与磁盘内容不变。

成熟设计参考为 ProseMirror 的上下文相关 clipboard slice 与代码上下文纯文本处理；只参考行为，不复制实现。规范参考 CommonMark 的转义、实体、代码边界与块优先级：

- [ProseMirror clipboard 实现](https://github.com/ProseMirror/prosemirror-view/blob/master/src/clipboard.ts)
- [ProseMirror MIT 许可证](https://github.com/ProseMirror/prosemirror-view/blob/master/LICENSE)
- [CommonMark 0.31.2](https://spec.commonmark.org/0.31.2/)

## 输入分派

1. 无可写笔记、空剪贴板：不修改。空白文本按普通文本处理，不触发结构导入。
2. 源码模式、代码块、公式源码、原始语法块内部：原样文本插入，不识别标题、TSV 或链接覆盖。
3. 明确的纯文本粘贴：绕过结构识别；保留字符，只统一换行。
4. 图片文件和图片数据：复用图片导入流程；不在本次改动中改变文本与图片混合剪贴板的选择规则。
5. 可编辑正文选区 + 单个 URL：保留现有链接覆盖行为。
6. 有效内部块副本：恢复结构，不依赖目标 Editor 私有缓存才能成功。常规块复制使用带版本、纯文本匹配校验和 Markdown 载荷的 metadata；未知版本或损坏载荷回退为普通文本输入。
7. 表格单元格上下文：先判断 TSV 或单元格文本，不将 Markdown 文档嵌成表格内的文档。
8. 正文中的明确 Markdown：统一解析并按块或行内片段插入。普通一句话与普通换行文本保持原有输入体验。
9. 矩形 TSV：仅在空正文或单元格空光标处转换；至少两行两列且列数一致。带有意义首尾空格或不满足条件时保留字面文本，禁止通过 trim 丢数据；代码上下文不转换。
10. 无明确结构特征：普通文本替换；解析失败的语法片段保留原文，不能静默丢失。

结构特征基于解析结果：标题、列表、引用、任务、代码、表格、图片、提示块、分隔线、有效 HTML 包装、实际行内格式或实体解码差异。单个井号、URL 查询符、孤立括号不能自行触发块替换。

仅含一个普通段落的富文本是行内片段，在光标处合并；显式块语法与整篇复制按块插入。换行统一 CRLF/CR 为 LF；BOM 只在文档开头处理，正文中的同码字符不删除。

## 全部块的适配契约

| 类型 | 导入与编辑结果 | 保存与边界 |
| --- | --- | --- |
| 正文 | Unicode 文本与 Span 保持；普通文本保持现有插入方式 | 不重复解码实体；UTF-8 范围必须落在字符边界；空白与软/硬换行分别核验 |
| 空段落 | 语法所需分隔空行不额外显示为空块；用户显式空块保留 | 不无条件 trim 文档；复制多次后空块数量不增长 |
| H1–H6 | ATX、Setext 与已有 HTML heading 转为对应级别；H4–H6 保留 metadata | 空标题、闭合井号、中文标题和与分隔线的歧义按解析器规则处理 |
| 无序列表 | 保留项目顺序、缩进和行内格式 | 不把 continuation 拆成无关列表；超出现有模型的多段嵌套整体保留源码 |
| 有序列表 | 保留非 1 起始编号、层级及列表边界 | 不因插入位置误继承上一列表编号；超范围数字不溢出 |
| 待办 | `[ ]`、`[x]`、`[X]` 恢复勾选状态与缩进；点击可切换 | 保存再打开状态一致；复制插入不重置已完成项 |
| 引用 | 简单引用保持 Quote 和行内标记 | 多层引用、引用内复杂块不能压平丢语义；暂不支持的容器完整保留源码 |
| 提示块 | NOTE/TIP/IMPORTANT/WARNING/CAUTION 与多行内容保留 | 相邻提示块不合并，未知类型保留原文，普通引用不被吞入 |
| 代码块 | 反引号、波浪线围栏，语言、缩进、正文与空代码块保留 | 内部 Markdown/HTML/实体均为字面文本；重新导出围栏长于正文中同符号连续段；未闭合围栏按规范至 EOF |
| 缩进/嵌套代码 | 能完整映射才转可编辑代码块 | 当前模型不能完整表达时整体源码回退，不能删缩进或把代码当列表 |
| Mermaid | 作为带语言的代码块进入现有渲染与源码编辑入口 | 语法错误时源码可访问，不因渲染失败改变文档 |
| 数学公式 | 独立 `$$` 与已支持 math 围栏沿用公式块 | 源码保持字面意义；不支持的行内/嵌套公式不假装转换成功 |
| 图片 | Markdown 图片与已支持 HTML img 恢复 alt、src、title、宽度及对齐 | 缺失图片仍保留引用；外部文本来源不明时不猜原目录、不批量复制附件；图片原文与附加属性不能静默丢弃 |
| 分隔线 | Markdown 或 HTML hr 恢复现有分隔块 | 与 Setext、frontmatter 竞争按上下文判定；前后文本不被合并 |
| GFM 表格 | 保留表头、行列、对齐、空格内格式、转义竖线和空单元格 | 管道符位于代码/链接中不得误分列；不规则或不可表示内容整体源码回退 |
| HTML 表格 | 保留表头、列宽、行列合并、属性及单元格链接/格式 | 不重复实体解码；未编辑外壳保留；范围上限、跨度重叠、缺标签、嵌套表格均验证后再写入 |
| HTML 段落 | 已支持 p/div/heading 包装恢复可编辑内容与属性 | 保持外壳；兼容旧版本在 HTML 包装内输出的 Markdown 链接和粗体，仍按旧混合语法解析，字面 Markdown 标点的歧义暂保留；新编辑内容输出完整 HTML |
| Frontmatter | 仅文档开头识别已有 YAML frontmatter 格式 | 插入到正文时保存为显式源码块，不偷偷成为目标笔记 metadata |
| 未知块 | 脚注、引用定义、复杂嵌套、自定义容器、原始 HTML 无损保留 | 源码回退按完整构造分组，范围有边界；不执行脚本、不删除未知属性、不冒充已可视化适配 |

支持等级必须明确：原生可编辑、已有专用视图、无损源码回退。覆盖所有类型意味着每类都有确定结果，不意味着未实现的容器已能可视化编辑。

## 行内契约

- 粗体、斜体、删除线、行内代码：既接受 Markdown，也接受已支持的 HTML 标签；重叠范围输出有效嵌套。
- 链接：标签、href、title 和范围保留；括号、中文、空格及实体正确处理。裸 URL 保留既有识别逻辑。
- 实体：仅语义解析阶段解码一次，`&amp;lt;` 最终为字面 `&lt;`，不能变成标签。`&#42;` 不能生成第二轮 Markdown 标记。
- 转义：反斜杠转义后的标点保持字面字符；代码区不使用普通正文的解码规则。
- 样式属性：已支持的高亮、下划线、颜色等沿用现有 InlineTag 表达；无法正确表示的片段保留来源，不直接丢标签。
- 引用式链接、脚注和跨行标记必须通过文档级上下文解析或完整源码回退；不能逐行处理后声称语义等价。

## 插入位置与事务

| 目标位置/选择 | 确定行为 |
| --- | --- |
| 空笔记的唯一空段落 | 用导入块替换占位空段落，不留额外前导空块 |
| 非空段落开头/结尾 | 块片段插在边界，原有段落不被覆写；行内片段直接合并 |
| 段落中间 | 保留头尾文本与格式；块片段置于两者之间，行内片段按偏移合并 |
| 单块选区 | 一次替换所选范围；新结构不继承与其不相容的旧 metadata |
| 跨块选区 | 保留首块前缀与末块后缀，完整替换中间；先确认跨越的表格是整表选择 |
| 表格单元格内部 | 普通文本留在单元格；矩形 TSV 按现有可编辑表格规则填充；复杂文档作为字面文本，不能拆散外层表格 |
| 部分跨单元格选区 | 不支持时明确拒绝，保留文档和选区；不得先删除再回退 |
| 整张表格/整块选择 | 整体替换；与行列选择、块选择的优先级一致，不只参考 caret |
| 代码、公式、原始块内部 | 原样替换文字，选择整个块则走整体替换规则 |
| 图片/分隔线的块光标 | 插在明确块边界或替换显式块选择，不能向图片 src 或分隔线字符串插入正文 |

事务不变量：

1. 解析和构造替换片段期间不改变 Editor；返回结果区分“不适用”“已处理”“拒绝”，拒绝不能继续落到文本替换。
2. 写入前校验可编辑上下文、选择范围、UTF-8 边界与目标表格限制；metadata 和表格资源限制沿用现有解析器，不新增统一的全类型资源配额。
3. 输入法组合按既有规则提交，随后获取一次 snapshot；删除、切块、插入、光标移动与列表缓存更新属于同一事务。
4. 新块分配新 ID，保留的块不能重复 ID；块数量、虚拟列表与索引一致。
5. 光标落在插入内容末端，原子块按既有可达位置处理；一次 Undo 恢复原文和选区，一次 Redo 恢复粘贴结果。
6. 解析失败或不支持结构时保留原文；表格超过现有解析上限时按源码保留，不能部分导入后丢弃剩余内容。
7. 当前解析同步执行；未来如采用异步解析，提交时必须校验笔记身份、文档版本与选择未变化，不能将旧结果写入新笔记。

## 实施分工与约束

主会话负责本设计与审查。用户指定 Grok 子代理实施；需操作电脑时指定 GPT-6.1 Terra 子代理。已发现 Magpie 路由 `remote/group/grok`，两个实施子代理的会话运行元数据均确认使用该模型，推理强度为 high。

建议拆分两项互不重叠的实施任务：

1. 粘贴事务：新增独立 paste 模块，修改 `input.rs` 接线和 `block_shortcuts.rs` 旧粘贴入口；覆盖选区与原子撤销，不更改 Markdown 解析实现。
2. 解析适配：审查 `markdown*.rs` 的块/行内边界，修复实际复现的解析或往返缺陷；不改剪贴板分派与事务。

集成后再派验收子代理运行临时检查。每个手写文件不超过 300 行，不新增永久测试，不新建分支。工作区已有 `src/editor/view.rs` 的无关修改，保持原状，不混入本任务提交。
