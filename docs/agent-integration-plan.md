# Block 本机 AI 接入：方案与验收状态

本文件记录实施范围与当前证据；编译通过不代表原生界面、账号授权或端到端验收通过。工作在现有 `main` 工作区进行，保留无关改动。

## 目标与架构

- 保留 Block 内置 AI；增加 Codex、Claude 和 dsh 本机后端，禁止外部后端失败时静默切回内置。
- 每个会话固定后端并持久化原生会话 ID；切换后端开始新会话，保留输入草稿与引用。检测可执行文件、版本、认证和失败状态，认证与订阅授权须以实际结果及官方条款为准。
- 顶部选择后端，输入框底部选择该后端的模型；原来的上下文范围下拉已移除。`@` 列表将当前笔记放在首项并去重，发送时保留当前笔记与实时选区上下文。
- 内置 AI 使用现有服务商模型列表与配置；Codex 通过 app-server `model/list` 获取候选，并在会话启动或恢复时传递模型 ID；Claude 使用本机 CLI 初始化响应的 `displayName`/`value`，以 `--model` 传值，未选值时跟随 CLI 默认。目录可来自用户的 Magpie 配置，不等同订阅授权。
- dsh 提供已核实的 `deepseek-flash` 与 `deepseek-v4-pro` 候选，并保留用户自定义模型；每轮 SDK 初始化传递 provider/model。未配置时 `deepseek-flash` 是应用回退，不代表用户原生默认。模型选择存入 Block 配置，不改写外部 CLI 配置。
- 每轮通过结构化子进程协议处理会话、流式输出、停止、错误和审批。公共运行时取消工具等待，拒绝迟到请求；各适配器负责子进程与线程清理。
- Block 提供受约束的笔记工具：实时读取当前未保存正文和选区；写入先生成计划，现有笔记经原有确认，纯新建保留原有自动应用行为。计划保存目标根目录与每页原文，应用前检查变化；写入失败报告错误并保留成功部分的撤销凭据；撤销前检查后续编辑。
- 文件写入与撤销会检查 Block 内部的根目录、当前内容和编辑状态，但不提供跨所有进程的全局原子事务：不遵守同一锁约定的外部程序仍可能在检查后、写入前修改文件。
- Codex 使用 app-server 动态工具和只读策略；该工具能力依赖版本，外部 MCP 被禁用。Claude 启动本机未修改 CLI，以 stream-json 和 Block MCP 通信，保留显式 user/project Skills，禁止 Bash、Write、Edit 等直接写入工具，外部 MCP 禁用；不读取或复制订阅凭据，不承诺订阅授权。dsh 通过本机 MCP 桥接和受限工作目录接入；其实际环境和能力需独立验收。各后端的 Skills 和 MCP 行为不同，不承诺共享配置。

参考入口：[Codex app-server](https://developers.openai.com/codex/app-server/)、[Claude Agent SDK](https://platform.claude.com/docs/en/agent-sdk/overview)、[DeepSeek Harness](https://github.com/deepseek-ai/DeepSeek-Harness)。版本支持、许可与账号条款须在正式交付前复核；不得仅凭 SDK 存在推断订阅登录可授权。Claude SDK 与帮助页有关订阅使用的表述需按具体产品和当前官方条款核对，不在界面承诺可用。

## 界面方案

- 方案 A：原生会话内切换及状态展示，作为实施默认；新版设计由 Gemini 4 Argon high 重做，之后由 Grok 实现。
- 方案 B：以会话列表突出后端归属，供比较。
- 方案 C：以集中设置和会话状态区组织后端，供比较。

三版初稿与 HTML 变更说明已交付，样式 A 为最终推荐；新版原生窗口验收仍进行中。
