Block Agent 后端交互说明

最终推荐为「样式 A · 聊天栏选择」。画板的笔记、模型、状态和消息均为示例，不代表实际账户或连接结果；原生实现和实际后端行为以验收结果为准。

最终推荐：样式 A

  • 聊天栏顶部选择后端；输入框左下选择该后端提供的模型，不再显示引用范围下拉。
  • 输入 @ 或点击引用按钮打开笔记菜单。当前笔记固定为首项；搜索按输入匹配，其他笔记按身份去重，不重复当前笔记。原有选区引用能力保留。
  • 引用菜单锚定输入区上沿，限高并在内部滚动，依据可用空间调整，避免遮挡和裁切最后一项；支持键盘选择。
  • 切换后端新建会话，清除旧消息、计划、审批和运行状态，保留笔记正文及未发送草稿和引用；历史会话仍属于原后端。
  • 模型目录动态取自当前后端；状态使用简洁文案，界面语言跟随应用设置。审批和修改建议保留确认、拒绝及撤销流程。

初版三种入口对比

方案交互取舍
一 · 聊天栏选择顶部选择内置 AI、Codex、Claude 或 dsh；切换后端开启新会话。初版推荐方向；最终样式以「样式 A」为准。
二 · Agent 入口先选择 Agent，再查看该 Agent 的会话。会话归属清晰，进入聊天多一步。
三 · 工作区管理在 AI 管理页设置新会话默认后端，右侧保留聊天栏。适合集中管理，切换需要进入管理页。

共同交互目标

  • 每个会话固定所属后端；切换后端开启新会话，不把旧消息当作新后端的原生上下文。历史会话显示其所属后端。
  • 保留笔记引用和选区；运行中可停止，失败时显示原因并保留可重试的草稿。
  • 审批请求由对应后端或 Block 工具实际发出时显示允许和拒绝；笔记修改经现有变更计划展示、确认、应用与撤销。
  • 状态以实际检测结果为准：检测中、可用、未安装、未登录、版本不支持或不可用。认证无法判断时展示检测结果及原因，不标为可用。

原型操作

进入「样式 A」画板播放模式，可演示后端切换、新会话、模型与引用选择、审批及修改建议；「演示状态」仅供模拟。其余三块画板保留为初版方案对比。

实施边界

  • 内置 AI 保留现有路径；本机后端状态、会话绑定和请求执行由核心接入，界面不自行推断可用性。
  • 笔记模式仅使用 Block 桥接的笔记工具，不隐式启用外部 MCP。技能和工具入口只展示当前后端实际支持的能力。
  • 画板中的审批和笔记修改是交互目标，不表示每个后端已支持相同审批机制或写入能力。失败恢复、撤销冲突与实际宿主行为仍需验证。
